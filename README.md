# Mojikko — 文字コードをそろえる

実行ファイルのダウンロード.
https://github.com/k518-2026/Mojikko/releases

テキストや CSV の文字コードを自動で見分けて、**UTF-8（BOM 付き）** にそろえる Windows アプリです。
Excel で CSV を開いたときの文字化けを防ぐのが主な用途です。

2026-11-02 に CsvBomConverter と TextFileProcessor（UTF-8 Converter & Merger）を 1 つにまとめて作りました。
元のソースは `E:\ClaudeCode\_archive\merged-2026-11-02\src\` にあります。

## 使い方

1. ファイル・フォルダー・ZIP をウィンドウにドラッグ＆ドロップする（「ファイルを追加…」「フォルダーを追加…」でも可）
   - 追加した時点で文字コードを読み取り、一覧に表示します
   - ZIP は中の CSV・TSV・TXT などを取り出して一覧に並べます（Google フォームの回答 ZIP など）
2. 「すること」を選ぶ
   - **1 つずつ UTF-8（BOM 付き）に変換する**: 同じフォルダーに `名前_BOM.拡張子` を作ります。
     ZIP の中のファイルは、ZIP の隣の `ZIP 名_BOM` フォルダーに、ZIP の中と同じ構成で書き出します
   - **一覧の順に 1 つのファイルへ結合する**: 「▲ 上へ」「▼ 下へ」で順番を決め、保存先を選びます。
     「2 つ目以降の 1 行目（CSV の見出し）を除く」「ファイルの切れ目に区切り行を入れる」を選べます
3. ［変換する］（結合のときは［結合して保存…］）を押す

元のファイルは書き換えません。同じ名前のファイルがあれば ` (2)` などを付けます。

## 文字コードの見分け方

外部ライブラリは使わず、次の順に調べます。

1. BOM（UTF-8・UTF-16 LE/BE・UTF-32 LE）
2. BOM なしの UTF-16（半角文字の上位バイトが 0 になる並び）
3. 英数字だけのとき: ISO-2022-JP（JIS）のエスケープ列があれば JIS、なければ ASCII
4. UTF-8 として正しく読めれば UTF-8
5. Shift_JIS と EUC-JP の両方の規則で読み、合わないバイトが少ないほう。両方とも読めるときは、
   Shift_JIS として読むと半角カナばかりになるなら EUC-JP、そうでなければ Shift_JIS

自動判別が外れるときは、「読み込み」で文字コードを指定できます。
Shift_JIS は Windows の CP932（①・髙 などの機種依存文字を含む）として読みます。

## CSV の確認

CSV・TSV でダブルクォーテーション `"` の数が奇数のものは、どこかで壊れている可能性があるので
「1 つずつ変換」では書き出さずに飛ばします（旧 CsvBomConverter と同じ）。結合のときは警告を出して、そのまま結合します。

## ビルド

- .NET 8 SDK。NuGet パッケージは使いません
- `dotnet build Mojikko.slnx -c Release`
- 単一 exe の発行は AppHub で行います: `apphub release Mojikko`

## 確認したこと（2026-11-02）

同じ日本語の文章を Shift_JIS・EUC-JP・UTF-8（BOM あり・なし）・UTF-16 LE（BOM あり・なし）・ISO-2022-JP・ASCII で保存し、
短い文（「テスト」だけの Shift_JIS、「日本語のテキスト」だけの EUC-JP）も含めて、すべて元の文字列に戻ることを確かめました。
名前が Shift_JIS の ZIP と UTF-8 の ZIP の両方で、中の CSV を取り出して変換できることも確かめています。

自動判別は推定です。大事なデータは、変換後のファイルを開いて確かめてから使ってください。
